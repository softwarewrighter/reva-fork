SQLite in the desktop app through host calls (rust/DESIGN.md 3.11). The VM runs as wasm in a Web Worker: reva-web surfaces Status::HostCall to JavaScript (an export that returns the encoded request, one that resumes with the encoded response); reva-worker.js posts it to the page; the page calls a new Tauri command host_call; desktop/reva-desktop answers from reva-sqlite (database paths under the app's folder, never outside it, as for files); the worker resumes the VM. The plain browser answers 'SQLite is not available in the browser' (a clear stop, as for other unserved libraries). Tests: desktop smoke test (a db/sqlite session in --print-output batch mode), web smoke (the not-available answer), node test of the request/response encoding. Verify on the Mac in the desktop app: create a table, insert, select, restart, the data persists in the folder. Gate: just check.
