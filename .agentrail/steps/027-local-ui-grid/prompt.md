The TUI's renderer, one look everywhere (option 2, decided with the user 2026-10-31): components/ui's model (dialogs, boxes, edit panes, labels, buttons, status line, focus, keys) lays out into a grid of character cells (text, colour, attributes, cursor), a pure Rust component with goldens on the grid (no browser needed). Two thin backends draw the grid: this step's Yew backend, a monospace grid element (DOM or <canvas>) in the web page, which the desktop app shows too, with keys (function keys included), mouse and resize sent back as events; local-ui-terminal adds the crossterm backend for the CLI. The same TUI looks the same in the browser, the desktop app and the terminal. HTML widgets could come later as an extra renderer, not now.
